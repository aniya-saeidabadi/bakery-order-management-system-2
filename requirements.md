# System Requirements

## 1. Functional Requirements

Functional requirements describe what the system must do.

**ترجمه:**

# الزامات سیستم

## ۱. الزامات عملکردی

الزامات عملکردی توصیف می‌کنند که سیستم باید چه کارهایی انجام دهد.

### FR-01: View Products

The system shall allow customers to view bakery products and their prices.

**ترجمه:**

### FR-01: مشاهده محصولات

سیستم باید به مشتریان اجازه دهد محصولات قنادی و قیمت آن‌ها را مشاهده کنند.

### FR-02: Place an Order

The system shall allow customers to place orders by selecting products and specifying quantities.

**ترجمه:**

### FR-02: ثبت سفارش

سیستم باید به مشتریان اجازه دهد با انتخاب محصولات و تعیین تعداد، سفارش ثبت کنند.

### FR-03: Customize a Cake

The system shall allow customers to specify cake details, including size, flavor, and a custom message.

**ترجمه:**

### FR-03: سفارشی‌سازی کیک

سیستم باید به مشتریان اجازه دهد جزئیات کیک شامل اندازه، طعم و پیام سفارشی را مشخص کنند.

### FR-04: Select Pickup Date

The system shall allow customers to select a pickup date for their orders.

**ترجمه:**

### FR-04: انتخاب تاریخ دریافت سفارش

سیستم باید به مشتریان اجازه دهد تاریخ دریافت حضوری سفارش خود را انتخاب کنند.

### FR-05: Validate Orders

The system shall check that the required order information is provided before accepting an order.

**ترجمه:**

### FR-05: اعتبارسنجی سفارش‌ها

سیستم باید پیش از پذیرش سفارش، بررسی کند که اطلاعات لازم سفارش ارائه شده باشد.

### FR-06: Track Order Status

The system shall allow customers to view the current status of their orders.

**ترجمه:**

### FR-06: پیگیری وضعیت سفارش

سیستم باید به مشتریان اجازه دهد وضعیت فعلی سفارش خود را مشاهده کنند.

### FR-07: View Customer Orders

The system shall allow bakery staff to view customer orders and their details.

**ترجمه:**

### FR-07: مشاهده سفارش‌های مشتریان

سیستم باید به کارکنان قنادی اجازه دهد سفارش‌های مشتریان و جزئیات آن‌ها را مشاهده کنند.

### FR-08: Update Order Status

The system shall allow bakery staff to update order statuses, such as Pending, Preparing, and Ready for Pickup.

**ترجمه:**

### FR-08: به‌روزرسانی وضعیت سفارش

سیستم باید به کارکنان قنادی اجازه دهد وضعیت سفارش‌ها را به‌روزرسانی کنند، مانند «در انتظار»، «در حال آماده‌سازی» و «آماده تحویل».

### FR-09: Manage Products

The system shall allow the bakery manager to add new products and update product information and prices.

**ترجمه:**

### FR-09: مدیریت محصولات

سیستم باید به مدیر قنادی اجازه دهد محصولات جدید اضافه کند و اطلاعات و قیمت محصولات را به‌روزرسانی کند.

### FR-10: Manage User Accounts

The system shall allow the system administrator to manage user accounts and access permissions.

**ترجمه:**

### FR-10: مدیریت حساب‌های کاربری

سیستم باید به مدیر سیستم اجازه دهد حساب‌های کاربری و سطوح دسترسی را مدیریت کند.

## 2. Non-Functional Requirements

Non-functional requirements describe how well the system must operate.

**ترجمه:**

## ۲. الزامات غیرعملکردی

الزامات غیرعملکردی توصیف می‌کنند که سیستم باید با چه کیفیتی عمل کند.

### NFR-01: Usability

The system shall provide a simple and understandable interface for customers and bakery staff.

**ترجمه:**

### NFR-01: سهولت استفاده

سیستم باید رابط کاربری ساده و قابل‌فهمی برای مشتریان و کارکنان قنادی فراهم کند.

### NFR-02: Performance

The system shall display the product list within 2 seconds under normal operating conditions.

**ترجمه:**

### NFR-02: کارایی

سیستم باید فهرست محصولات را در شرایط عملیاتی عادی ظرف ۲ ثانیه نمایش دهد.

### NFR-03: Security

The system shall prevent unauthorized users from accessing restricted features.

**ترجمه:**

### NFR-03: امنیت

سیستم باید از دسترسی کاربران غیرمجاز به قابلیت‌های محدودشده جلوگیری کند.

### NFR-04: Privacy

The system shall protect customers' personal information from unauthorized access.

**ترجمه:**

### NFR-04: حریم خصوصی

سیستم باید از اطلاعات شخصی مشتریان در برابر دسترسی غیرمجاز محافظت کند.

### NFR-05: Reliability

The system shall store accepted orders accurately and prevent incomplete orders from being saved.

**ترجمه:**

### NFR-05: قابلیت اطمینان

سیستم باید سفارش‌های پذیرفته‌شده را به‌درستی ذخیره کند و ازذخیره شدن سفارش‌های ناقص جلوگیری کند.

### NFR-06: Compatibility

The system shall be usable on common modern web browsers.

**ترجمه:**

### NFR-06: سازگاری

سیستم باید روی مرورگرهای وب مدرن و رایج قابل استفاده باشد.

### NFR-07: Maintainability

The system shall be designed so that developers can update and maintain it easily.

**ترجمه:**

### NFR-07: قابلیت نگهداری

سیستم باید به‌گونه‌ای طراحی شود که توسعه‌دهندگان بتوانند به‌سادگی آن را به‌روزرسانی و نگهداری کنند.
